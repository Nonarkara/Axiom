# Axiom Security Audit

Started 2026-10-02; completed implementation review 2026-10-05. Scope: public
static site, local Node/SQLite server, evidence exporter and Pages workflow.
This is a targeted engineering review, not a certification or penetration test.

## Findings And Fixes

1. High: the public evidence snapshot contained nine private pipeline entries.
   Removed the pipeline payload and count from the static artifact and exporter.
   The private SQLite records remain intact. An isolated canary test verifies that
   creating and editing a private entry never adds it to the public export.
2. High: local admin reads and writes had no authentication. Added fail-closed
   environment-configured Basic authentication, loopback-only binding, exact Host
   checks, cross-site protection and socket-address rate limiting. Basic auth is
   suitable only for this loopback development listener, not remote HTTP hosting.
3. Medium: the visitor tracker sent IP/location/fingerprint data to a third party.
   Removed that script. Local pageviews now omit query strings, referrer paths,
   user-agent fingerprints and country headers. Cloudflare aggregate analytics
   remains; this does not claim the third-party provider collects no identifiers.
   Replaced the stale footer claim about a nonexistent 12-character visitor hash
   with accurate provider/request-metadata wording in all seven locales.
4. Medium: request bodies and stored URLs were too permissive. Enforced bounded
   JSON objects, HTTP(S)-only credential-free URLs and bounded text fields.
   Fixed string-to-boolean conversion for the contract flag.
5. Medium: static serving needed realpath containment and protected-path checks.
   Traversal, hidden/configuration files and outside/admin-alias symlinks are
   blocked. Status responses no longer disclose the database filesystem path.
6. Medium: browser and supply-chain controls were missing. Added a hash-based CSP,
   framing/MIME/referrer/permissions protections, pinned Leaflet SRI and immutable
   GitHub Action references. No CI file-specific prechecks were added.

## Verification

- Native Node tests cover authentication, validation, private exports, traversal,
  symlinks, response headers, pageview privacy and rate limiting.
- Local JavaScript syntax checks and generated-header consistency checks pass.
- Browser desktop verification retains map tiles, animated canvas, HUD, city
  selection, AUTO TOUR and headline rotation with no logged CSP errors.
- Gitleaks scanned 298 commits and reported 24 generic-api-key matches. All 24
  were verified against parsed historical translation JSON as exact localization
  identifiers, not credentials. The scan is not proof that no secret can exist.
- Production publication and live checks are recorded in the shipping commit and
  deployment run, rather than asserting an unperformed penetration test here.

## Remaining Risks

- Private pipeline records remain recoverable in earlier Git history and older
  Pages deployments. Removing the current public artifact does not erase copies.
  History rewriting, deployment deletion and any notification assessment require
  a separate, coordinated remediation decision; none were performed here.
- Existing historical analytics rows were not purged. Their retention policy
  remains an owner decision. New collection is minimized.
- Pages is static: it does not run the local authenticated Node API. Its admin
  viewer can read only deliberately public evidence. Remote administration needs
  a separate HTTPS/access-control deployment.
- CSP retains inline styles for Leaflet and current HTML, and external font,
  map-tile and pinned library hosts. It disallows arbitrary inline scripts/eval
  but does not replace output encoding or access control.
- No WAF, production credential rotation or destructive history changes were
  made. There are no runtime npm dependencies in the landing-page server.
