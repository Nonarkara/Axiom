# Axiom Security Audit — 2026-10-21

Second pass, after the reading room's artwork plates, the hero decision console
and the multilingual work landed. Scope: the two deployed static sites
(`axiom.nonarkara.org`, `axiomx.nonarkara.org`), the local Node/SQLite server,
the QA and spatial-gate tooling, and the two Pages workflows. A targeted
engineering review — not a certification and not a penetration test.

The previous pass is `cso-audit-2026-10-05.md`. Everything it fixed was
re-verified and still holds; the findings below are new.

## Findings And Fixes

1. **Medium — the reading room carried no security headers at all.**
   `axiom/_headers` held one rule, a cache lifetime for `/art/*`. There was no
   content security policy, no `X-Frame-Options`, no HSTS, no
   `Permissions-Policy` and no `nosniff` on a public surface that serves a
   hundred-plate book in seven locales. The reading room is now covered by the
   same set as the catalogue: a policy that names every origin the room
   actually loads (Google Fonts, `youtube-nocookie` frames, YouTube
   thumbnails, the catalogue's own mark), framing denied, a transport policy, a
   permissions policy and `nosniff`.
   *Verified by enforcement, not by inspection:* the policy was attached to
   every same-origin response in a real browser and the room was loaded. No
   console errors, no failed requests, 214 CSS rules applied, fonts loaded,
   zero broken images.

2. **Medium — every unknown address answered 200 with the homepage.**
   `/this-path-does-not-exist`, `/api/admin/bootstrap`, `/api/admin/case-studies`
   and `/.env` all returned the full 213KB homepage with a success status.
   A URL that claims to be an API answered with HTML and a 200; a scanner read
   every probe as a hit; a crawler could index an unbounded number of copies.
   Both sites now carry a `404.html` that says so, in the house language, and
   answers with the status the request deserves.

3. **Medium — a third-party video frame loaded itself.**
   The reading room's field-video player created the `youtube-nocookie` iframe
   the moment an entry rendered. That is a request to a third party the reader
   never made, on the one page of the book that claims to report ground truth,
   and it cost the reader the bandwidth and the reader's attention. The
   player now holds the same poster the catalogue already uses, and the film
   arrives on one click. No `youtube-nocookie` request is made before that
   click — checked by counting requests on the wire.

4. **Low — the admin workspace is publicly readable on the static build.**
   `/admin/` is served from the static deployment with no authentication,
   because the Basic auth lives in `server.mjs`, which is not deployed. What it
   exposes is the public evidence snapshot: three case-study records, twelve
   public timeline entries and aggregate pageview counts — all of which the
   public site already publishes, in `public/data/evidence-snapshot.json`. Its
   writes go nowhere, because `/api/*` does not exist on the static host. The
   build marks the path `noindex` and `no-store`.
   *Residual:* an internal tool is still visible to the public. Putting it
   behind Cloudflare Access is a dashboard change with no repository
   expression, so it is left to the owner rather than guessed at.

5. **Low — the admin's form could not show its own values.**
   Twelve fields sat in a 100px track and clipped their content: a badge read
   `CASE_01 //`, a client read `Strategic intelligence ope`, a URL read
   `https:`. An operator could not read the value they were about to
   overwrite. Fields are now sized by what they hold — an enumeration shares a
   row, a sentence takes the row, a URL takes the row — and the two panels
   that framed a void around their own content were restructured into one band
   each. All twelve clips are gone.

6. **Informational — the gate's `--base` proxy made a subdirectory page
   unmeasurable.** The proxy injected `<base href="{origin}/">` into every HTML
   response it forwarded, so a page under `/admin/` resolved its stylesheet and
   its script to the *site* root, arrived with no CSS and no JavaScript, and
   was measured as a clean page with 1,546 characters of unstyled HTML. A
   false green for a page that was never rendered. The base now points at the
   route's own directory. The measuring probe itself is byte-identical to the
   package; the change is in the Node-side harness.

7. **Informational — one falsifier rule had never been tested.** The
   "a page the baseline has never seen" rule builds a synthetic page and
   expects the gate to fail on it. The page was called `__never-seen__`, and
   the gate skips underscore-prefixed directories on purpose — a partial, not
   a page — so the page under test was ignored and the rule was unproven
   while the suite still read green. The probe route is now
   `never-seen-probe`. All thirteen rules bite.

## Verified Clean

- **No secrets in the shipped surfaces.** Pattern scan and high-entropy token
  scan across `public/`, `axiom/`, `lib/`, `scripts/` and `.qa/`: no API key,
  no token, no private key, no password. The deploy workflows hold only
  `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`, as repository secrets.
- **No XSS sink reaches untrusted data.** The i18n renderer escapes first and
  then re-allows a fixed whitelist of tags (`b`, `em`, `br` and three named
  span classes); the admin escapes every interpolated value, including the
  record list and the pipeline table; the reading room's only `innerHTML` is
  a static SVG dictionary in the repository. No inline event handlers, no
  `javascript:` URLs, on either site.
- **Every new-tab link is safe.** 113 `target="_blank"` links across the
  catalogue, the reading room and the admin; all carry `rel="noopener"`.
- **The catalogue's CSP is exact.** The two inline-script hashes in
  `public/_headers` match the two inline scripts in `public/index.html`,
  byte for byte, after re-running the generator.
- **The CDN dependency is pinned.** Leaflet's CSS and JS both carry a
  `sha256` integrity hash, and every GitHub Action in all three workflows is
  pinned to a commit SHA.
- **The local server is fail-closed.** It binds to `127.0.0.1` only, checks
  the `Host` header exactly, rate-limits per socket address, rejects
  cross-site mutations, and disables the admin entirely when
  `AXIOM_ADMIN_PASSWORD` is unset.

## Open For The Owner

1. **Cloudflare Access on `/admin/`.** The cleanest way to keep the internal
   tool internal. It is a dashboard change with no repository expression, so
   it was not guessed at.
2. **`access-control-allow-origin: *`** is set by Cloudflare Pages, not by
   this repository. It is harmless for a public static site with no
   credentials, and it is not something the build can turn off.
3. **PR #2 (draft, "Restore Shanghai self-hosted fonts")** commits fourteen
   base64 gzip fragments of `public/index.html` into the published directory.
   The Pages build would publish them, and the branch rewrites `index.html`
   and `app.js`, which have moved on since it was opened. It was not merged.
   Self-hosting the fonts is worth doing; the way that branch does it is not.
